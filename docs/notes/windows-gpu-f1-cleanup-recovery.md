# Proposed decision: one cleanup-only recovery, not a preflight retry

**Status: PROPOSED. Mac must rule on independently reviewed, committed source before execution.**
Rulings 217 and 220 authorized the prior bounded attempt and packet repair. This proposal
does not extend that authorization. No WSL command or recovery action ran during authoring.

Its checkpoint step failed with the recorded PowerShell `Substring` exception. It withheld
archive deletion and unregister, and reported `MAC-DECISION-REQUIRED`. The receipt reports
owned stop, protected snapshot and guard binding successful; those are historical reports,
not fresh recovery-time proof. No full dependency closure, package inspection, capacity
admission or F1 acceptance is claimed.

The original `Save-Checkpoint` is preserved byte-for-byte at
`docs/proof/win-gpu-f1-preflight/run-1/checkpoint/`: 75 payload files plus the original manifest.

inventory manifest. The original execution worktree and its evidence remain untouched.
Git attributes disable text conversion for both retained trees and any later recovery final tree.
`manifest.py verify` must prove every byte against the committed checkpoint before cleanup.
Recovery verifies the retained live inventory against Git and the original source as well.

## Ordered procedure and stop conditions

1. Verify the original 75-file freeze and its manifest anchor in both canonical and original
   locations. Run the real packet `manifest.py verify` against HEAD. Independently verify the
   retained live inventory and original live bytes. Any missing, extra, linked, changed or
   uncommitted evidence stops before cleanup.
2. Freshly compare registry identity, exact BasePaths, WSL list presence, version, and
   nonlinked host path ancestry for both distros. Refuse duplicate/missing identities,
   registration/list disagreement or GUID/path changes.
3. Use the real packet `owned-control.sh --mode check` for the original target stages and
   original protected guard. Inspection failure, residual groups, uncertain PID reuse,
   partial ownership or altered exact argv stops. Recovery does not stop unknown original work.
4. Capture a fresh full protected terminal snapshot with the real completed-L3 helper.
   Require its hash to equal the historical completed snapshot. Start a fresh CPU0/nice10
   completed-L3 guard with a distinct recovery session; require a current complete continuation
   row and matching state. Keep it running through unregister and a fresh post-unregister row.
5. Admit only `/var/cache/cfdw-f1-r217/r217-run1-epoch6-20261012` inside the exact target.
   The read-only cache check refuses linked ancestry, device changes, intersecting mountpoints,
   symlinks, directories and unexpected entries. Invoke only the existing packet's
   `delete-debs` stage under CPU0-1/nice10 and its recorded PID=PGID=SID ownership.
   No simulate, repository, download, inspect, install, source, build or CFD stage is callable.
6. In the deletion's unconditional finally path, freshly check target identity, run the
   packet's bounded exact-owner stop/reap and residual check for recovery-owned deletion,
   then recheck original target ownership. Any failed stop/reap blocks unregister. No target
   workload is launched after this final check. The guard still observes the protected distro.
7. Recheck identity and guard before exact `wsl.exe --terminate cfdw-petsc-cuda132-f1`, and
   again before exact unregister. Global shutdown, other-distro lifecycle changes, import,
   resizing and recursive host path removal are absent. If unregister leaves a path behind,
   recovery stops for Mac rather than deleting it.
8. Independently prove target absence from registry, WSL list and host path (including a
   dangling link), and unchanged protected registration. Wait for a new completed-guard row
   after unregister; require the fresh full terminal snapshot to equal the initial/historical
   snapshot. Request guard stop and independently stop/reap/check its exact group in finally.
9. Preserve all errors in a separate `cfdw-f1-cleanup-recovery/1` receipt. Freeze fresh evidence
   to `recovery-1/final/`; make a separate real Git commit; use packet `manifest.py verify`
   against that commit. A successful recovery never rewrites the failed original receipt.

Any guard stop/staleness, identity or evidence mismatch, unknown process state, child failure,
deadline exhaustion, residual path or final binding failure means **stop and Mac decision**.
There is no retry, catch-path unregister, cleanup fallback, authority widening or preflight rerun.
The whole deadline is monotonic and includes child startup; a killed Windows launcher is
recorded as unknown Linux state. If the deadline prevents final stopping or Git binding,
fresh live evidence remains available and success is withheld. No automatic push is performed
by recovery; the executor reports the separate committed receipt or its explicit binding failure.

## Offline proof and execution graph

Goal: a concrete independently reviewable recovery proposal. Done when source, refusal tests,
preserved bytes and offline gates are committed and pushed. Not in scope: live cleanup,
WSL execution, a repaired preflight, package acquisition or F1 build/benchmark. Tier T1;
one author, fan-out zero. Independent review belongs to the coordinator's next track.

Surface list: original evidence → inventory → committed Git blobs → authorization/ruling →
registry and ownership admission → continuous terminal guard → exact target lifecycle →
absence/invariance receipt → separate committed recovery evidence. UX/UI and product data-model
changes are N/A. The evidence grain is one frozen file; history is append-only snapshots and
receipts, with byte counts additive per freeze and terminal hashes non-additive.

The optimize-graph plan is a serial data-dependent chain: ground → red tests → source and
retention → offline checks → commit/bind → push/handoff. Source inspection and retained-file
reads share inputs and use bounded batched tools; implementation and gates remain sequential.
The naive and optimized plans have six nodes, width one, no recovery retry loop and all floors
present. Duration is measured by the audit marker; token cost and modelled timing are not recorded.
Any author repair loop is capped at two cycles; independent review can reject this proposal.

Verified red first: the offline test entry failed because the recovery module was absent.
Verified green: 16 tests execute the actual authorization/identity/absence validators, ordered
cleanup function, lifecycle action and deletion command builder. They plant changed bindings,
unbound checkpoints, duplicate/wrong identity, old-owned or guard failure, deletion failure and
final reap failure. The canonical 75-file inventory is read using real filesystem bytes. Tests
exercise exact command arguments through a boundary mock; they do not claim WSL fidelity.
Cache controls use real temporary files and mountinfo fixtures. Ring: offline-fast; measured
16-test suite cost 0.049 s before final documentation gates (normal unittest timing output).

Class → sweep → derive → prevent: recovery authority must not inherit broad preflight stages,
and cleanup must not erase a failed attempt. Sweep: all recovery dispatch branches, target
lifecycle argv, finalization callbacks, canonical/retained manifests and public path projections.
Controls: exact authorization dictionary; only three destructive actions; checkpoint-first
ordering; unconditional final owned-stop; retained original receipt and separate recovery receipt;
offline refusal fixtures. Existing R217 ownership/cleanup controls are reused rather than copied.

## Residual risks for the independent reviewer

Live WSL launcher/group teardown, registry race behavior, UTF-16 distro listing, mountinfo
interpretation, cache state, capacity and protected terminal invariance are unobserved in this
authoring track. Source/helper hashes and a newly accepted contract must be reviewed together.
The cache admission and deletion are separate operations: local concurrent cache mutation is a
remaining race; any such ownership concern blocks execution rather than broadening cleanup.
External WSL registry/path mutation between the final fresh check and lifecycle call cannot be
made atomic by this wrapper. Deadline exhaustion can leave cleanup/evidence binding incomplete;
the script must retain failure and request Mac direction. Offline tests establish refusal/control
logic, not live recovery acceptance. This proposal does not authorize F1 installation or execution.
