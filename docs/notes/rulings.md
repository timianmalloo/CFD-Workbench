### Ruling 3 — Expected rejection is successful negative-probe evidence

Clarifies and supersedes only the denial classification in Ruling 2. An expected denial of the predeclared protected-path negative probe is successful protection evidence when the protected sentinel remains byte-identical; it does not trigger route fallback. Do not retry or circumvent that protected operation. An unexpected denial of an authorized in-scope operation such as pwd, the permitted fixture edit, or build still ends the Agy route. Ordinary command failures are classified separately from permission refusals: a sandbox-local runtime cache initialization failure may be retried within the same five-minute qualification budget using task-local DOTNET_CLI_HOME and NUGET_PACKAGES, without changing HOME, broadening directories, weakening sandbox policy, or altering global trust. Preserve first failure and retry receipts. Each qualification record must name the expected-reject operation, its observed denial and unchanged-byte oracle separately from allowed-operation execution. A negative probe that actually changes the protected sentinel is a failed protection claim, never a successful denial. All other limits, fallback routes and independent gates in Ruling 2 remain.
