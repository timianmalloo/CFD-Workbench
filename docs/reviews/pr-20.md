# PR #20 — Fable owner review

PR #20 "docs: capture Windows WRI scale probe evidence" (origin/win/wri-p6-confirmation, reviewed head cab7ffca) was
reviewed by the Fable owner on the Mac on 2026-10-09 under Ruling 106. Verdict: **APPROVE WITH CONDITIONS**, issued as
**Ruling 178**. Each finding is Verified unless marked Inferred.

## Findings

1. **P1 and P2: the scale is Verified.** `instrumented.stdout.txt:1` reads "P2 RenderScaling=1.5;
   Screens.Primary.Scaling=1.5; WorkingArea=0, 0, 2560, 1528; UseLayoutRounding=True", on tested head 842e575d. The restore
   reading is at 93240b06. AppliedDPI is 144. TextScaleFactor was not recorded.
2. **P4: item 8 is red at 1.5, before WDF.** The TextBox is 23.333 DIP (35 px), and the padding applied is 2.667 DIP
   (4 px). 842e575d predates WDF's MinHeight fix, so this proves the defect, not the fix.
3. **P3: item 3.** After Show the window is 1400×1000 DIP. At 2100×1500 px it fits the WorkingArea, so there is **no
   clamp**. The layout clauses pass. The width is 1130.667 against 1133.333 − 2, and the 2.667 difference is the two
   1 DIP view-frame borders, each rounded to 1.333 DIP. It is not the menu bar.
4. **P5: items 4 and 5.** StationColor `#66ddc8` appears exactly at device resolution, so the border is present and the
   right colour. At scale 1, the 1 DIP border falls on a 2/3-DIP seam and splits across two pixels, so the sum-distance
   test fails. This is a sampling seam, not a defect. Inferred: the Elevation device-resolution block missed the chip
   edge.
5. **Item 6 is still open (Inferred).** The TextBox origin is itself snapped (0.667), which could make up the 1.0 DIP, but
   the fact TextBlock bounds were not printed.
6. **P6 is NOT ASSESSED.** It ran before Ruling 177, with an `AppliedDPI did not become 192` gate, on 93240b06 (no WDF).
7. **Gates.** The capture manifests match (4), PII shows 0, check-docs passes, and the diff is docs only.
