## Findings

1. **The script tested is the script on main.** The SHA-256 is `a79ac73c…` on main, at the PR head, and in
   `verifier.stdout.txt:3`. The blob `528b56d8` matches `process.json` `scriptBlob`.
2. **The stdout supports the claim.**
   - 12 PASS lines, plus 1 FAIL on the historical `WindowsNative_Replace_HeldReaderKeepsOldImage` (Win32 32).
   - `SUBSET … ran=13`, classifier `UNEXPECTED 0`, `PASS Windows store qualification checks=13 expected_failures=1`.
   - `TOTAL_WALL_SECONDS=19.466184`.
   - `TARGET_MET=false` is advisory (Ruling 175 (3)).
3. **Manifest and PII pass.** The manifest check gives "5 manifest(s) match", and `check-proof-pii.py` finds 0. No user
   path, SID or raw hostname was found by grep. Gap: `check-proof-pii.py:25-29` has no hostname rule, so Ruling 174's
   class has no control. This is a Mac follow-up, not a PR condition.
4. **The null exit is a launcher defect.** `process.json` has `processExited: true` but `processExit: null`.
   `watchdog.ps1:16` starts the child with `Start-Process -PassThru` and redirects, never caches `$child.Handle`, calls
   `Refresh()` (`:42`, `:45`) and then reads `ExitCode` (`:46`). The mechanism under Windows PowerShell 5.1 is Inferred.
5. **The residuals are SDK build servers, by design.** They are an MSBuild node (`/nodeReuse:true`), VBCSCompiler and two
   conhosts. The verifier disables only the MSBuild server (`verify-windows-store.py:742`). Its `_terminate_tree` runs
   only on timeout (`:132`, `:222`, `:231`). The FAIL rule is the watchdog's own (`watchdog.ps1:52`).
6. **The fail-closed disposition is right.** The receipt is `status: blocked`. Readiness admits Windows PASS only
   through a reviewed receipt. The PR touches no tool, source or test.
7. **Derived views.** A raw merge with main drops main's ECR/V3D index entries. They are regenerated at the join.
8. **Register gap.** The receipt has class/sweep/derive/prevent prose, but `defect-classes.md` is not touched.

Gates on the PR head merged with main:
