# PR #30 — Fable owner review

PR #30 "docs(proof): qualify OpenFOAM v2512 GPU route" (origin/win/gpu-g1-r197, head a656184c, proof head d691b06c) was
reviewed by the Fable owner on 2026-10-10 under Ruling 106. Verdict: **APPROVE WITH CONDITIONS** (**Ruling 199**). The
operator consented to B2 (**Ruling 200**). Each finding is Verified unless marked Inferred.

## G1 against Ruling 197 (c)
Every item is present. Paths are under `docs/proof/win-gpu-g1/`.
- **Source.** Commit 87ed40d2, SHA ae9a0a13…, GPL-3.0-or-later (`source.json:4-9`, `receipt.md:39-40`). Only the archive
  hash is committed.
- **Backend.** OpenMP-target pragmas sit in `ListExpression.H`, with a `par_unseq` fallback. The Nvidia rule is
  `nvc++ -std=c++17 -fopenmp`, without `-mp=gpu`, so a stock build offloads nothing. Umpire 2025.03.0 provides the pools
  (`receipt.md:65-69`; the upstream was re-fetched).
- **Reach.** Assembly only, never the linear solve (`receipt.md:70`).
- **`ldd`.** `libfusedFiniteVolume.so` and `libOpenFOAM.so` link no CUDA, nvomp, Umpire, PETSc or AmgX
  (`installed-linkage.stdout.txt:11-56`).
- **petsc4Foam.** OpenFOAM v1912+ and PETSc 3.10+ (`receipt.md:72`).
- **Rejected:** amgx4Foam (hard-codes CUDA 11.6) and RapidCFD (CUDA 8, Ubuntu 16.04) (`receipt.md:73-74`).
- **F1 bill of materials:** `receipt.md:60-74`.

## Observer
1. **The medians match Ruling 197 (b).** Recomputed from rows 1–8: before 0.7916, during 0.7733, after 0.7908, a change of
   −2.32 %.
2. **A clock-domain defect.** Each `sleep 600` advanced UTC by 647–655 s, while `/proc/uptime` advanced 600.04 s, a gap of
   8–9 % per interval and about 325 s in total. Host and WSL UTC agree to about 1 s, and the earlier wall-clock L3 rate of
   0.72 it/s matches the UTC-based rates (0.728–0.735). So `/proc/uptime` in this WSL2 VM likely runs about 8 % slow, and
   the absolute 0.79 it/s is not a wall-clock rate. The relative verdict holds on both clocks: −2.32 % (monotonic) and
   −2.99 % (UTC). OBS-CLOCK-DOMAIN-A is corrected at this join.
3. **Append-only, but hashed whole.** `samples.jsonl` only ever gains lines, and no manifest binds it. But
   `observer-window.json` and the receipt hash the whole growing file, so that claim cannot be checked after the next
   append. Future receipts bind an N-row prefix hash or a snapshot.
4. The 5 % rule was evaluated after the fact. For any multi-minute step it must run live.

## Route (Rulings 199, 200)
- **Closed on this machine:** the native-fused nvc++ route. It offloads assembly only, needs the 10+ GB NVIDIA HPC SDK with
  unpinned flags, and is documented only on unified-memory parts.
- **The route with payoff:** petsc4Foam plus PETSc built with CUDA, which puts the linear solve on the GPU.
- **B1, read-only, no install.** One core under nice 10, observer live, 10-minute ceiling. It records:
  - the driver's CUDA ceiling;
  - free disk;
  - whether `wmake` and the v2512 dev headers are present;
  - `apt-cache policy cuda-toolkit` on ubuntu2404 (metadata only);
  - the PETSc `--with-cuda` contract.

  It produces a pinned F1 recipe.
- **B2 (operator-approved, Ruling 200).**
  - Install the CUDA toolkit into a **separate disposable WSL distro**, never `cfdw-openfoam2512`. The rollback is
    `wsl --unregister`.
  - Run a toy managed-memory offload test outside OpenFOAM.
  - Bounds: 2 cores under `taskset` and nice 10; the observer live, with the 5 % rule on each row and both clocks; no L3
    path touched; a manifest-bound receipt with an N-row prefix hash.
- **F1 stays closed** until B2 reports.
