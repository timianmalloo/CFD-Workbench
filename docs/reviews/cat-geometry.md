# Catalog determinism — computational-geometry review

On 2026-10-08 the Mac leader convened the computational-geometry expert in Adversary mode, read-only, on
`docs/proof/cat/investigation.md` (track CAT). The datum comes from the Windows ring (Ruling 154 class d):
`naca-0009` generated bytes, 6686 vs 6686, first differing byte 727. That byte is a 1-ulp difference in
`Math.Cos(Math.PI*i/80.0)` at `Catalog.cs:197`. **Verdict: PASS-WITH-CONDITIONS, option A.** The veto is not cleared
until P1–P5 hold, the residual is reported, and the Windows bits match.

## Pre-build conditions

- **P1.** Every value on the generator path uses only + − × ÷ √. Either copy the cosine kernel into Core, or pin
  `double.CosPi` with a committed 81-value bit golden.
- **P2.** The 4412 frame is sqrt-only: sinθ = slope/√(1+slope²), cosθ = 1/√(1+slope²), and the frame rotation from
  (mx, −my)/length. The recorded `rotation` column is never compared with `!=` against a C-runtime value.
- **P3.** The Placement path changes too: `Placement.cs:117` uses `double.SinCosPi(deg/180)`, and `:209` and `:697`
  use `CosPi`. Then `placement-surface-bits` is re-recorded once.
- **P4.** The residual against `/1` is recorded in the decision note.
- **P5.** No cross-OS determinism claim until the Windows ring is green on the A build.

## Findings

1. **[Blocker for D]** `m12d-catalog.md:163` says "regenerate bit-for-bit from generator id + version", so D weakens
   spec text and is operator-only. Separately, `Naca0012Reference.cs:19` calls `CatalogGenerator.Naca4("0012")` rather
   than the shipped bytes: a second evaluator (GEO-A). It should read `Catalog.Load()` whatever option is chosen.
   Verified.
2. **No stored project breaks.** Projects store only the provenance `gen:<id>` (`WorkbenchController.cs:1544`,
   `Provenance.cs:65-81`), and Replace writes the fitted spline. The change from `/2` against `/1`:
   - 0009 and 0012: 60 of 161 points change, max 2.2e-16.
   - 4412: 160 of 161 points change, max 1.50e-11 chord; rotation 9.3e-10°; scale −5e-14.

   All are far below the 1e-6 identity tolerance. Follow-up: provenance carries no generator version, so a future
   change above the tolerance needs a new catalog id. Verified.
3. **[Major]** The 4412 LE golden-section search amplifies a 1-ulp trig change about 1000×, moving ordinates by
   1.5e-11. Windows may differ more than the 0009 datum shows. Verified.
4. `double.CosPi` is managed, uses only + − ×, and is not [Intrinsic]. `AtanPi` and `Atan2Pi` call the C runtime.
   Spacing accuracy is |s − exact| ≤ 2⁻⁵² (measured 1.10e-16, against 1.90e-16 today), with s₄₀ = 0.5 exactly.
   Verified against the release/10.0 source.
5. **[Major]** "Deterministic across OS" rests on two things: no FMA contraction, and the PC's bits matching. It is
   Inferred.
6. The recorded `rotation` column needs atan2. Either store direction cosines, or compare degrees within 1e-12
   relative. Today only `CatalogTests.cs:158` reads it. Verified.
7. **[Major]** `placement-surface-bits` stays a bit golden only once its path is free of C-runtime calls. Otherwise it
   must become a 1e-12 relative tolerance. Verified.
8. The record-write path has the same class: `SectionReplace.cs:327`, `DatImport.cs:386` and `:524`,
   `ConstrainedFit.cs:281` and `:400`, and `FoilSource.cs:654`. This does not trigger the veto, because the written
   bytes become the record. Sweep it as a follow-up. Verified.

## Tests and controls

- (a) The Windows-ring generated-bytes check.
- (b) An 81-value spacing bit golden.
- (c) A gate banning C-runtime transcendentals on an explicit file list (Catalog.cs and the Placement spacing and
  twist sites).
- (d) A spacing-accuracy test: ≤ 2⁻⁵², exact endpoints and midpoint, monotone.
- (e) The residual report.
- (f) A defect-class entry: a bit golden on a C-runtime transcendental is a platform-keyed authority.
