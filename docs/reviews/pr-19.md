# PR #19 — Fable owner review

PR #19 "tools: add bounded Windows store verifier" (origin/win/store-verifier-r171, reviewed head 4cd25c4f) was reviewed
by the Fable owner on the Mac on 2026-10-09 under Ruling 106. Verdict: **APPROVE WITH CONDITIONS**, issued as
**Ruling 175**.

## Findings

1. **Ruling 171 (1) is met (Verified).** `_close_streams_bounded` (:115-122) closes the streams on a daemon thread,
   joined for at most 0.02 s. `_terminate_tree` (:125-201) caps every wait under one 2 s cleanup deadline. The process
   start time is captured at line 7, before the imports. The 1.05 s green is the sum of the bounded waits
   (0.5 + 0.5 + 0.02 s), not a faster version of the old blocking call. The red 2.016905 s is the probe's own join cap
   firing; it is a correct red, but the number is a cap, not the length of the block (Inferred).
2. **A minor deviation (Verified, :332-333).** The probe's deadline expires inside `communicate`, so cleanup still
   starts with its full 2 s budget. The branches for a deadline already past at cleanup entry are not exercised.
3. **Exit 4 on the Mac (Verified, from a scratch worktree of the head).** It prints `NOT ASSESSED: this verifier
   requires Windows`, then `TOTAL_WALL_SECONDS=0.053070`, and exits 4 in 0.29 s. The self-test exits 0, but the skipped
   pipe probe still prints a `SELFTEST PASS` label (:316, :683).
4. **Check selection (Verified).** The 13 checks are both pinned (:50-64) and discovered (:275-297). An added,
   missing, duplicate or non-literal check fails the run (:777-784), so a stale set fails loudly, and zero checks fails.
   The expected failure is keyed by name, and agrees with the Windows manifest.
5. **Scope (Verified).** Nothing under src/ or tests/, and no edit to run-readiness.py or verify-application-core.py.
   `.gitattributes` gains 3 lines (`-text` on the proof captures); acceptable.
6. **Privacy and captures (Verified).** 0 PROOF-PII hits; 3 capture manifests match; check-docs exits 0.
7. **The evidence gap (Verified).** The only no-argument Windows run (13 ran, one expected failure, 15.309 s) is script
   `f257d9a2` at a9b1fed3. The head script is `92151a8f…`, with no Windows run.
8. **Readiness wiring (Mac).** `run_ring` gives one timeout to every entry, and prints FAIL for any non-zero exit
   (`run-readiness.py:100-138`). The wiring needs a per-entry 60 s timeout, and exit 4 mapped to NOT ASSESSED before the
   FAIL print.
9. **Hygiene.** `docs/proof/win-store-implementation/capture-integrity.py` duplicates `tools/check-capture-manifests.py`.
   checkpoint.md has three "final SHA-256" values; only the last is current.

## Ruling 175

- (1) Ruling 171 (1) is met.
- (2) The 13-check PASS counts as evidence only for the earlier script. Windows PASS enters readiness only through a
  receipt from a rerun of the final script.
- (3) The 15 s target stays advisory.
- (4) The Mac wires readiness: a per-entry 60 s timeout, and exit 4 = NOT ASSESSED, never FAIL.
- (5) Follow-ups:
  - (PC) a zero-budget probe variant;
  - (PC) SKIP labelling off Windows;
  - (PC) one no-argument rerun on the final script;
  - (PC) reword the superseded SHA lines;
