## Scope and method

The affected chain is accepted FoilDSL bytes → core-owned draft/assessment →
accepted identity and history → native image/store → controller → visual and
accessible views, with CLI consuming the same core. The bounded C milestone
allows an independent numeric LE/TE control edit and sparse certified points;
it is not the complete v7 section-profile editor or a simulation implementation.

Root freezes compiled worker checkpoints in separate scratch directories and
uses independently written consumer programs and actual CLI subprocesses.
Each later consumer disables implicit MSBuild item discovery and asserts runtime
assembly hashes before launch. Local .NET/NuGet/temp roots and observed PID/start
identities bound these runs; this is observed containment, not a sandbox claim.
Retained raw receipts live under `/tmp/cfd-adapter-review.3sSb4H` and
`/tmp/cfd-controller-review.B2SeOB`. They are local evidence, not portable product
assets. The descriptions and fingerprints below remain reviewable without them.

## Native UI proof status

Medium: native desktop. Targets: macOS and Windows. Framework: Avalonia 11.3.14
on .NET 10.0.203. Distribution in this increment: unsigned development `.app`
and Windows portable directory; no signing, notarization, public deployment or
trust-setting change is claimed.

Root's native inspection tool failed with `cgWindowNotFound -10005` for observed
app paths/IDs, including an instrumented build and uniquely identified copied
bundle, and after one supported tool reset. Startup logs reported the window
opened, but logs are not rendered proof. Root has not obtained a valid screenshot,
native AX tree or a keyboard-driven app interaction. A user visibility question
is pending. Subsequent materially changed final builds may be inspected; repeated
identical attachment failures are not useful progress.

The following remain **Not assessed**: rendered layout/craft; actual macOS AX
and Windows UIA; full keyboard traversal and OS dialogs; theme/high contrast;
window/DPI behavior; dense-list response; native review harness states; measured
interaction budgets; Gatekeeper/SmartScreen behavior and Windows runtime.
Source token/contrast checks and managed peers are separate evidence. The browser
59-rule CSS craft detector is inapplicable to native XAML, not a zero-file PASS.
No screenshot or AX artifact should be invented to complete the path inventory.

## Evidence corrections

An initial root hypothesis named an eta-near-root CV as editable. Inspection
showed that CV was locked; the actual reproducer uses editable eta .9 controls.
The corrected all-editable sweep is retained. A scratch consumer initially loaded
an older same-named DLL through implicit MSBuild file discovery. Its API mismatch
was a test-harness defect, not a production failure. Root disabled default items,
specified exact references and asserted runtime hashes; the corrected selected-eta
run above uses the intended five-assembly manifest. This class is captured as
TEST-A by the Coordinator.

Other setup corrections were a missing app-local Blake3 native mapping for a raw
assembly consumer and an initially guessed missing-file diagnostic. Root copied
the exact frozen runtime library app-locally and asserted the observed stable
refusal. These setup failures remain in raw logs and are not counted as product
regressions. The Coordinator also records CO-UI: a worker's direct OS window probe
was stopped and is not accepted native proof; all further UI interaction must use
the approved native UI tool.

Final acceptance requires source-bound final verification, completed author proof,
independent native review, Owner disposition and Coordinator join. An unavailable
platform or inspection tool remains a named obligation rather than a passing gate.
