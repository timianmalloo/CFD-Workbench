# UI review — as-built Avalonia Desktop workbench

*Produced by `/ui-design` (mode: **review**). Governed by `ui-design-craft.md` DX22–DX25 over the floors in
`ui-interaction-design.md` (U1–U20), `technical-ui-design.md` (TQ1–TQ12), and the native-client standard
(`UI-T4`). Every finding carries location · dimension · severity · evidence · fix · confidence. Severity uses the
4-point template scale (`4` Blocker · `3` Major · `2` Minor · `1` Nit); any accessibility finding at `≥ 3` is
promoted to **Blocker (a11y)** per U16/CD12.*

- **Surface(s) reviewed:** Complete as-built Avalonia Desktop client (`src/CfdWorkbench.Desktop/`, 58 `.cs` + 19 `.axaml` = 77 source files excluding `obj/`/`bin/`, 26,338 LOC at `main` `285b765e`), plus user-facing copy in `src/CfdWorkbench.Analysis/{Labels,SectionDisplay,AnalysisProjection}.cs` and test proof coverage in `tests/CfdWorkbench.Desktop.Tests/` (44 test files, 782 checks).
- **Reviewed against:** `DESIGN.md` (§1–§12) · `docs/design/workbench-direction.md` · `docs/specs/cfd-workbench-v1.md` · Archetype `ParametricWorkbench` (G1) + `ScientificVisualization` (G2, Analysis).
- **Reviewers:** Author pass (three parallel surface inspections: Shell & Chrome, CAD & Inspector, Analysis & Proof) + independent Adversary Panel (`UX & Accessibility` hard veto · `UX Researcher / IA` UX veto · `Native Desktop Developer` · `Simplifier` · `Test Architect`).
- **Date:** 2026-11-21 · **Mode:** review (read-only code & test inspection; no product files modified).

**Archetype check against the job to be done:** The workbench targets **G1 Parametric Modeling Workbench** (serial editing through one selection and one inspector over a dominant spatial canvas) paired with **G2 Scientific Visualization Pipeline** in Analysis (parallel reading of loading curves, polars, Cp profiles, and run comparisons sharing the same geometry canvas). The core CAD-to-Analysis canvas sharing holds structurally (**Verified** in `ModelArea.axaml` and `AnalysisToggleTests.cs`), and the Premiere-Pro-style Structure B property grid (`PropertiesPane`) aligns well with serial precision input. However, shell chrome has drifted materially from `DESIGN.md` §5 (F-07), and several broken interactions violate the basic contract of a native desktop document editor (F-01 through F-03).

## 1. Verdict

> **BLOCK** — Strong domain honesty (TQ5 uncertainty/omissions copy, `vik`/`batlow` palettes, Structure B property grid, and 782 local desktop harness checks) is undermined by 15 Blockers across file data safety (`Save As…` overwrite, missing dirty guard), Command Palette breakage, 1.01:1 hover and High Contrast readability failures, broken Analysis/Section views (including an unreachable Compare pane), and unverified native OS accessibility/DPI/signing gates.
>
> **Highest-leverage change (DX25):** Tighten `Styles.axaml` interaction states and custom-canvas theme/contrast bindings in one focused ~120 LOC pass (**P0-B**: replace aggressive `Button`/`TabItem`/`ListBoxItem` hover inversions with soft surface fills, add `OnSelectionBrush` on `PointsPane` selected rows, fix nonexistent `"AccentBrush"`/`"WarnBrush"` keys in `SectionChartView`, and wire `ActualThemeVariantChanged` on `View3d` and all 3 Analysis canvases) — eliminating 3 accessibility contrast Blockers (`F-04`, `F-06`, `F-16`) and 2 cross-surface craft/theme Majors (`F-15`, `F-17`) in a single low-risk change. *(Stop-ship data-safety prerequisite: **P0-A** `F-01`/`F-02`, ~40 LOC.)*

|---|---|---|
| **Blockers (Sev 4, incl. a11y ≥ 3)** | **15** | 9 functional/layout Blockers + 6 Accessibility findings promoted to Blocker under U16/CD12 (`F-04`, `F-06`, `F-12`, `F-13`, `F-14`, `F-16`) |
| **Majors (Sev 3)** | **16** | Architecture/IA drift, precision editing gaps, layout collisions at 1024×700, UI-thread spin loops, LAB-01 copy defects |
| **Minors (Sev 2)** | **11** | Responsive/scaling gaps, token bypasses in C#, Imperial unit leaks, dead scaffolding |

**Accessibility veto:** **BLOCK** (confirmed by independent `UX & Accessibility` Adversary) — clears when all five falsifiable predicates pass and are independently re-verified:
1. `Button:pointerover`/`Button:pressed` on `StartView`, `CatalogDialog` `ListBoxItem.disabled` hovered/selected rows (`F-04`), and `PointsPane` High Contrast selected rows including `pts-cell.ro` (`F-06`) measure ≥ 4.5:1 text contrast across Light, Dark, and High Contrast; `SectionChartView` series (`F-16`) measure ≥ 3.0:1 WCAG 1.4.11 and honor HC tokens;
2. `F6` cycles all live dock regions (`Properties`, `Layers`, `Points`, `AnalysisPanel`, `ModelArea`, `Toast`, floats), dialog focus return hits live controls (`F-08`), `ToggleLeftSidebar` restores focus (`F-14`), and `PlanCanvas`/`ElevationView` support keyboard station focus + `Space`/`Return` (`F-12`);
3. OS High Contrast and OS Reduced Motion are honored automatically (not review-env-only), High Contrast Fluent/Dock overrides and child-dialog `RequestedThemeVariant` propagation are complete, and `ExportDialog`'s indeterminate `ProgressBar` obeys reduced motion (`F-13`);
4. All AT semantics in `F-14` are fixed (`RightToolDock` close button, missing `LiveSetting` regions including `StartView.AlertPanel`, `ModeReason`, `AddPointError`, `RebuildPopover.ErrorText`, `AnalysisPanel.PanelBanner`; `ExportDialog` radio `LabeledBy` + initial focus; `FindAlphaDialog` `IsDefault`/`IsCancel`/focus/`LiveSetting`; `SectionCanvas` `ModeCanvas` name + `CurvePointLayer.PointPeer`; `PointsPane` `Speech.Unit`; `UnitsButton` & `BrowserPane` rail names), `LoadingChart`'s table twin scrolls (`F-10`), and modal dialogs do not clip at 200% text scale (`F-23`, WCAG 1.4.4);
5. Live Windows NVDA/UIA and macOS VoiceOver traces are recorded and cleared by an independent `UX & Accessibility` reviewer (never the author).
