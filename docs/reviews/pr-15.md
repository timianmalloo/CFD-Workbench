# PR #15 — Fable owner review

PR #15 "W-2: limit Windows ProductCode mapping" (origin/win/store-product-code, reviewed head c5f3e2a2) was reviewed by
the Fable owner on the Mac on 2026-10-08 under Ruling 106. Verdict: **APPROVE WITH CONDITIONS**, issued as
**Ruling 166**.

## Findings

1. **ProductCode (Verified).** `WindowsNative.cs:260` reads
   `internal string? ProductCode => Win32Error == 32 ? "DOC-CONFLICT" : null;`. The only references in src are the
   definition; the tests assert it twice. No null flows anywhere. Today an unmapped Windows native failure is an
   `IOException` (`WindowsNative.cs:253`), which `ProjectStore.cs:84-85, :161` reports as DOC-IO, shown through COPY-412
   (Rulings 148 and 155). Inferred: no product surface changes, because ProjectStore stays fail-closed on Windows.
2. **Test (Verified).** `docs/proof/win-product-code/red-first.md` shows it red on Windows ("Expected ; actual
   DOC-IO"), then green, with the same selector. It asserts 183 maps to null. It is Windows-gated, and the Core test
   project compiles on the Mac.
3. **Design §4 (Verified).** `windows-native-store.md:182-191` states DOC-CONFLICT for 32 and null for every other value,
   "not a general Win32-to-product-code table".
4. **The ring.** The chronology is Verified; the attribution is Inferred.
   - The ring ran on e2d2b5cc. Its parent 7c3d4d07 has the manifest but not the CAF or RWF joins; those came in with
     the merge at the head, and no ring ran after it.
   - Failures: Core 36 (against 30 Core manifest entries), Analysis 2 (catalog determinism and the wing-run budget),
     CLI 2 (both listed), Desktop 2 (fail-closed store).
   - The six extra Core failures and the catalog Analysis failure are Ruling 154 classes (d) and (f), fixed by CAF
     (Inferred).
   - Nothing names this PR's test, which passed.
   - The 168.6 s wall is the Windows regime (the WFX2 ring took 140 s under six-CPU affinity), not a regression from a
     5-line diff.
   - On `proc-gitbash` the time budget is advisory (`check-test-costs.py:45-49, :103`) until
     `docs/proof/ring-windows/baseline.csv` exists, so the exit of 1 comes from the unexpected failures, not the budget.
5. **COPY-447.** Noted: the leftovers a crash leaves can be measured only in a later slice. Not a condition here.
6. **Privacy and scope (Verified).** 0 PROOF-PII hits, and every file is inside the PC lease.
7. **Audit (Verified).** The two PC entries carry a checkout path with no `Users` segment. `audit-log.py verify` is
   green.

## Ruling 166

- (1) Ruling 152 (4) is closed by the limited mapping, the §4 text and the unmapped-183 control.
- (2) The 168.6 s ring is a failed ring on a pre-CAF/RWF base, not evidence against this PR. The time budget stays
  advisory on the Windows host until a baseline exists.
- (3) Follow-ups, listed under Conditions.
